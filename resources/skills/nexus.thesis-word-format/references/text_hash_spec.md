# 文本完整性基线与 Hash 计算规范 (`text_hash_spec.md`)

学术论文排版的核心铁律是：**格式允许调整，内容绝不篡改 (Formatting is allowed; content mutation is forbidden)**。
为了对“内容零篡改”进行可数学验证的审计，本系统构建了严格的文本哈希基线机制。

---

## 一、为什么不能直接对整个 DOCX 文件取 Hash？
DOCX 是一个 ZIP 压缩包，只要修改了一个样式、调整了边框或更新了页码，内部的 `word/styles.xml`、`word/document.xml` 的 XML 属性就会发生改变，整个文件的 SHA-256 必然会变。
因此，必须提取**具有学术语义的正文文本**并计算其稳定的内容哈希。

---

## 二、文本哈希覆盖范围 (Inclusion Scope)

哈希计算**必须覆盖**以下包含用户学术思想的内容：
1. **所有正文段落 (`<w:p>`)** 中的纯文本内容；
2. **所有表格单元格 (`<w:tc>`)** 中的数据与文本内容；
3. **脚注 (`<w:footnote>`) 与 尾注 (`<w:endnote>`)** 中的引用与补充说明文本；
4. **图表题注与说明文字**。

---

## 三、动态字段排除规则 (Exclusion Rules)

为了防止在合法排版操作（如刷新目录、重算页码）时引发“伪 FAIL”，哈希计算**严格排除**以下动态计算字段：

| 排除字段 | XML 标识 | 排除原因 |
| :--- | :--- | :--- |
| **目录字段结果** | `<w:instrText>TOC ...</w:instrText>` | 刷新目录时，页码点线和标题页码会发生自然变动，属于排版预期行为。 |
| **当前页码** | `PAGE` | 随着边距和行距变动，排版后页码数值会动态改变。 |
| **总页数** | `NUMPAGES` / `SECTIONPAGES` | 排版后总页码数量可能增减。 |
| **页引用** | `PAGEREF` | 引用的目标页码随排版变动。 |

---

## 四、空白字符归一化规则 (Whitespace Normalization)

1. **段首伪缩进空格**：
   - 很多作者用敲 2~4 个空格或全角空格 `\u3000` 代替 Word 首行缩进。
   - 当用户明确授权清理伪缩进并应用段落原生 `FirstLineIndent` 时，归一化算法会将段首用于模拟缩进的空白字符剥离后参与哈希计算，确保文字语义本身未丢失。
   - 若用户未授权清理伪缩进，则严格保留所有原始字符计算哈希。
2. **段内换行符**：统一将 `\r\n` 与 `\r` 规整为 `\n`。

---

## 五、合格判定准则 (Verification Threshold)

```text
before_text_hash == after_text_hash  => PASS (文本绝对零篡改)
before_text_hash != after_text_hash  => FAIL (内容被篡改，立即阻断交付)
```
禁止使用“肉眼看起来没变”作为通过标准。
