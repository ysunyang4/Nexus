# Academic Thesis Word Formatting & Verification (`nexus.thesis-word-format`)

## 一、定位与设计理念

> **这不是论文写作 AI，不是论文润色 AI，不是降重工具，也不是内容编辑器。**
> 
> 它是一个面向毕业论文、学位论文、开题报告等 Word 文档的**受控格式化、结构诊断、规范映射、独立验证与审计系统**。

核心原则：
* **Formatting is allowed; content mutation is forbidden.**（允许调整格式，绝对禁止篡改内容）
* **When uncertain, stop rather than guess.**（遇到歧义或存疑，暂停并询问，绝不擅自猜测）
* **宁可少改，也绝不能误改。**

---

## 二、六大不可违反铁律

1. **Rule 1 — 原件绝对只读**：
   - 严禁直接修改或覆盖用户的原始 `.docx` 文件；
   - 必须先在同目录下建立 `[备份]_原文件名_YYYYMMDD_HHMMSS.docx` 并校验 SHA-256；
   - 所有排版操作仅在独立工作副本上进行，最终输出为 `[已排版]_原文件名.docx`。
2. **Rule 2 — 内容绝对零篡改**：
   - 严禁改写句子、润色段落、修改实验数据、删除公式或变更参考文献内容；
   - 只能调整属于“样式属性”的对象（字体、字号、行距、缩进、边框、页边距、对齐、大纲级别、字段刷新）。
3. **Rule 3 — 建立内容完整性基线**：
   - 排版前计算正文文本的稳定 SHA-256（排除动态 TOC 与页码字段）；
   - 排版后若 `before_text_hash != after_text_hash`，直接判定 **FAIL**，拒绝交付。
4. **Rule 4 — 对象完整性保护**：
   - OMML 公式、MathType、OLE 对象、图片、图表、脚注、尾注等默认视为原子不可变黑盒，禁止通过“纯文本重建”导致对象丢失。
5. **Rule 5 — 对象数量严格守恒**：
   - 公式、图片、表格、脚注、OLE 对象等数量在排版前后必须守恒，任何受保护对象数量意外减少直接判定 **FAIL**。
6. **Rule 6 — 杜绝伪 PASS**：
   - 任何 PASS 必须建立在“Save -> Close -> 重新打开 -> 独立 OOXML 解析校验”之上。未覆盖渲染项标为 `NOT_TESTED`。

## 三、SOP 分步执行流水线

```text
[PHASE 0] 只读审计 / 环境体检 (Audit Only, 零写文件，诊断排版缺陷)
   ↓
[PHASE 1] 规则对齐与规范解析 (解析用户规范 PDF/DOCX 或加载基准模板，输出参数清单)
   ↓
[USER CONFIRMATION] (若存在歧义规则 AMBIGUOUS 或复杂合并表格，等待用户确认)
   ↓
[PHASE 2] 备份创建与完整性基线建立 (生成 [备份] 文件，清点对象数量与文本 Hash)
   ↓
[PHASE 3] 页面与分节引擎 (A4、页边距设置、断开页眉页脚 LinkToPrevious)
   ↓
[PHASE 4] 标题与正文样式刷 (中西文双字体分离、20磅/1.5倍行距、样式级首行缩进2字符)
   ↓
[PHASE 5] 学术三线表与图表题注 (顶底1.5pt/栏目0.75pt/无竖线，复杂表格保留并 REVIEW)
   ↓
[PHASE 6] 目录与参考文献 (调用 Word 原生 Fields.Update() 刷新目录与页码)
   ↓
[PHASE 7] 保存并关闭 (Save & Close)
   ↓
[PHASE 8] 独立重开验证 (独立 OOXML 重新比对文本 Hash 与对象守恒)
   ↓
[PHASE 9] 交付与审计报告产出 (生成 [已排版]_原文件名.docx 与 [排版报告]_原文件名.md)
```

---

## 四、执行状态模型

系统严格采用以下 5 种确定性状态：
* **PASS**：全部铁律与核心检查项独立验证通过。
* **FAIL**：文本被篡改、对象数量减少、文件损坏或排版致命异常。
* **BLOCKED**：前置条件不满足（原件缺失、文档加密受保护、文档含修订标记、备份失败）。
* **REVIEW**：存在格式歧义、复杂合并表格或疑似标题段落，需用户人工确认。
* **NOT_TESTED**：当前环境（如缺少 MS Word 官方版面渲染器）无法视觉打样的项目，明确告知用户。

## 五、CLI 命令行调用方式

本 Skill 自包含 Python 引擎位于 `engine/`，可通过本地 Python 或 Nexus Runner 调用：

```bash
# 1. Phase 0 只读审计（绝不修改文件）
python engine/cli.py audit "E:/论文/我的毕业论文初稿.docx"

# 2. 执行完整受控排版（使用默认硕博标准模板）
python engine/cli.py format "E:/论文/我的毕业论文初稿.docx"

# 3. 指定学校官方规范执行排版
python engine/cli.py format "E:/论文/我的毕业论文初稿.docx" --spec "E:/论文/清华大学研究生学位论文规范.pdf"
```

## 六、交付物说明

每次执行完成后，用户工作目录下将呈现：
1. `原文件名.docx`：**原始文件，绝对只读，SHA-256 毫发无损**；
2. `[备份]_原文件名_YYYYMMDD_HHMMSS.docx`：**安全备份副本**；
3. `[已排版]_原文件名.docx`：**排版完成的正式交付成果**；
4. `[排版报告]_原文件名.md`：**详尽的审计报告，附带参数追溯矩阵与状态核对表**。
